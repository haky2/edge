# 예측 보조 기능 6종 — 작업분석서

> 2026-07-04 작성. 클로드 코드 구현용 인계 문서.
> 배경: "어떤 종목을 매수하려는데 실제 어느 방향으로 흘러갈지"를 돕는 신규 기능.
> 방향 단정("오를 확률 70%")은 환각이므로 금지 — **과거 기저율(비슷한 조건에서 실제로 어디 갔나) + 트리거(어떤 조건이 나오면 방향이 확정/무효되나)** 프레임으로만 접근한다.

## 공통 원칙 (전 기능 적용)

- **계산=사실, LLM=해석.** F1~F4·F6은 LLM 호출 0. F5만 매수 기록 시 1회 호출.
- 표본 작으면 과신 금지: n<15이면 "참고 수준" 명시(기존 C9 규칙과 동일 기준). n은 항상 표기.
- 캐시: 계산 결과는 당일 파일 캐시(`FileCache` 재사용). 개인 데이터(F5)는 `.data/`(캐시 아님, 영속).
- vertical slice: 각 기능은 "백엔드 1 엔드포인트 → 앱 1 카드"가 독립으로 돌고 검증까지 끝나야 다음.
- 유닛테스트: 순수 계산 함수는 companion/object로 분리해 테스트 필수(RegimeDetector/computeEvents 패턴).

## F1. 유사 국면 통계 (StateAnalog)

### 목적
매수 검토 시점의 종목 상태와 유사했던 과거 시점들을 찾아, 그 이후 5/20/60거래일 실제 수익률 분포를 보여준다. "지금 사면 어디로 가나"에 대한 기저율 답변.

### 설계
**상태 벡터** (전부 기존 계산 재사용 또는 일봉에서 산출):
- 52주 위치(%) — quote 또는 일봉 252일 고저로 계산
- 최근 20일 수익률(%)
- 거래량 비율(당일/20일 평균)
- RSI14 (Wilder — sharedLogic `TechnicalIndicators`와 동일 산식으로 백엔드 재구현, 값 일치 테스트)
- 수급 연속일(외인 기준, 부호 포함: +3=3일 연속 순매수) — InvestorFlow 이력 필요(아래 데이터 이슈)

**유사도**: 피처별 z-정규화(해당 종목 과거 분포 기준) 후 유클리드 거리. 거리 하위 k=30 또는 임계값 이내. **연속일 중복 제거**: 채택된 유사일로부터 ±5거래일 이내는 하나로 클러스터(같은 국면을 중복 집계하면 n 부풀려짐).

**출력**:
```
GET /analog/{code} → {
  code, date, vectorToday: {...},          // 오늘 상태(설명용)
  n: Int,                                   // 유사 국면 수(클러스터 후)
  horizons: [ {days: 5, winRate, median, avg, min, max},
              {days: 20, ...}, {days: 60, ...} ],
  peersIncluded: Boolean,                   // 동종 표본 포함 여부
  caveat: String                            // n<15 등 자동 문구
}
```

**표본 확장**: 자기 이력만으로 n이 부족하면 `PeerValuationService.SECTOR_PEERS` 바스켓 종목의 과거도 포함(피처가 전부 상대값·정규화라 종목 간 비교 가능). 포함 여부는 응답에 명시.

### 데이터 이슈 (구현 전 확인 필수)
1. **일봉 이력 길이**: `KisClient.getDailyChart`가 1회 호출로 몇 건까지 주는지 확인(FHKST03010100, 현재 기본 62·백테스트 120 사용 중). 250~500거래일이 필요하므로 부족하면 기간 파라미터(FID_INPUT_DATE_1/2)로 페이지네이션 추가 + 과거분은 파일 캐시(불변 데이터라 영구 캐시 가능).
2. **수급 이력**: `getInvestorFlow(days=5)`만 쓰고 있음 — 과거 수급 연속일을 벡터에 넣으려면 이력 API 한도 확인. **한도가 빡빡하면 v1 벡터에서 수급 피처를 빼고 4피처로 시작**(가격·거래량 피처만으로도 성립). 수급은 v2.

### 슬라이스
- 1a: 일봉 이력 확장(페이지네이션+영구 캐시) — `curl`로 500일 확인
- 1b: 상태 벡터·유사도·클러스터링(순수 함수 + 테스트) → `GET /analog/{code}` (자기 이력만)
- 1c: iOS/Android 상세 카드 "유사 국면"(분포 막대 + 승률/중앙값 + n·caveat)
- 1d: peer 표본 확장(옵션)
- (옵션) analysis facts에 한 줄 주입 — "유사 국면 n=23, 20일 후 중앙값 +4.2%" (C9 가드 적용)

### 테스트
z-정규화·거리·클러스터 중복 제거·horizon 수익률 계산 각각 유닛. 엣지: 이력<60일, 분산 0 피처(상장 직후), 유사일이 최근 60일 이내라 forward return 미확정(제외 처리).

### 리스크·한계
- 과최적화 냄새가 나면 안 됨: 피처 5개 이하 고정, 가중치 튜닝 금지(전부 동일 가중). 튜닝하고 싶어지면 F6 데이터가 쌓인 뒤 검증셋으로.
- 카드 문구에 "과거 분포일 뿐 미래 보장 아님" 고정 표기.

## F2. 수주 공시 임팩트 통계

### 목적
수주·공급계약 공시 발생 시 "이 종목의 과거 같은 카테고리 공시 이후 주가가 실제로 어떻게 반응했나"(1/5/20일)를 보여준다. 방산·조선 관심종목에 직결.

### 설계
**6-0 (최우선, 즉시 구현): 이벤트 로그 신설.** 현재 `verdictStore`(code|url→판정)에는 날짜가 없어 시계열 조인 불가. `CatalystService` 판정 시점에 append-only 로그 기록:
```
.data/catalyst_events.jsonl — {code, date, source(공시|뉴스), category, sentiment, strength, preReflected, url}
```
`PersistentMap` 패턴 말고 jsonl append(이벤트 로그는 수정 불필요, 무한 누적 후 기간 프루닝).

**백필**: 수주·공급계약은 DART 제목 룰(`ruleCategory`)만으로 분류 가능 → LLM 없이 과거 1~2년 공시를 배치 백필 가능(`dart.getDisclosures` 기간 확장 필요 여부 확인 — DART list API는 bgn_de/end_de 지원). 백필분은 sentiment=호재/strength=미상으로 두고 카테고리·날짜만 신뢰.

**통계**: 공시일 기준 forward return(1/5/20거래일, 일봉 조인). 분해 축: 카테고리별 / 선반영 여부별(preReflected).
```
GET /catalyst-impact/{code}?category=수주·공급계약
→ { n, horizons: [...], preReflectedSplit: {reflected: {...}, fresh: {...}}, caveat }
```

### 슬라이스
- 2-0: 이벤트 로그 기록(신규 판정분부터) — **지금 바로**
- 2-1: DART 백필 배치(수주 카테고리만, 룰 분류)
- 2-2: 통계 계산 + 엔드포인트 + 테스트
- 2-3: 앱 — 재료 카드의 수주 항목에 통계 한 줄 ("과거 유사 공시 7건: 익일 +3.1%, 선반영 시 +0.4%")

### 리스크·한계
- v1은 발생 빈도·반응만. 계약 금액/연매출 비율 분해는 v2(공시 상세 API에서 금액 파싱 필요).
- 공시일이 휴장일이면 다음 거래일 기준으로 정렬(effectiveMarketDate 로직 참고).

## F3. 실적 발표 프리뷰 / 리뷰

### 목적
실적 발표 D-7부터 "서프라이즈 여지"와 "이 종목의 과거 발표일 반응 패턴"을 보여주고, 발표 후엔 run-rate 대비 실제를 자동 채점. "실적을 들고 넘어갈까"에 데이터로 답한다.

### 설계
**프리뷰** (실적 캘린더 D-7 이내 종목):
- 서프라이즈 여지: 연환산 run-rate(기존 `forwardPerLine` 로직의 연환산 값) vs 전년 동기 실적 — "run-rate 유지 시 YoY +X%" 계산치 제시. 컨센서스 EPS는 무료 소스가 없으므로 **추정치 비교는 하지 않는다**(목표가 추세로 간접 대체).
- 과거 반응 패턴: 기존 실적 캘린더 로직이 최근 18개월 정기공시 접수일을 이미 알고 있음 → 과거 발표일들의 익일/5일 수익률 통계(일봉 조인). "이 종목은 최근 6번 발표에서 익일 평균 -1.2%(소문에 사서 뉴스에 파는 패턴)" 같은 사실.

**리뷰** (발표 감지 시): 새 분기보고서 접수 → 실제 분기 순이익 vs 직전 run-rate 예상 → "예상 상회/부합/하회" + 다음날 브리핑 노출.

```
GET /earnings-preview/{code} → { dDay, runRateYoY, pastReactions: {n, day1Avg, day5Avg, winRate}, caveat }
```

### 슬라이스
- 3a: 과거 발표일 반응 통계(순수 함수 + 테스트) + 엔드포인트
- 3b: 브리핑 "실적 일정" 섹션 확장(D-7 이내 종목에 프리뷰 붙임)
- 3c: 발표 감지 리뷰(스케줄러 일일 잡, DART 신규 정기공시 폴링 재사용)

### 리스크·한계
- run-rate 연환산은 계절성 미반영(기존 forwardPerLine과 동일 한계) — 문구 고정 표기.
- 발표 "시각"(장중/장후)에 따라 익일 정의가 달라짐 — v1은 접수일 다음 거래일로 통일.

## F4. 수급 전환점 알림

### 목적
외인/기관이 N일 연속 순매도 후 **첫 순매수로 전환한 날**(또는 반대) 장 마감 후 알림. 브리핑의 "3일 연속 순매수"는 추세 확인이고, 이건 변곡 감지.

### 설계
- 룰: 직전 5거래일 연속 순매도 → 당일 순매수 전환(확정 일별값). 반대 방향(연속 순매수→첫 순매도)도 대칭.
- 필터: `flowSensitivity`에서 해당 주체 상관 r≥0.3·confident인 종목만(수급이 가격을 안 움직이는 종목의 전환은 소음).
- 발송: 기존 Slack 연동으로 v1(채널: 기존 브리핑 채널 재사용 또는 신설). FCM 푸시는 Phase 5 푸시 인프라 때 승격.
- 잡: Cloud Scheduler 16:30 KST(수급 확정 후) → `POST /jobs/flow-reversal-scan`(내부 토큰 보호, 기존 잡 라우트 패턴) → 관심종목 순회.
- 메시지에 백테스트 근거 병기: "이 종목 외인 순매수 신호 익일 승률 62%(n=8, 참고 수준)".

### 슬라이스
- 4a: 전환 감지 순수 함수 + 테스트(연속일 계산은 StockAnalysis 수급 요약 로직 참고)
- 4b: 스캔 잡 + Slack 발송 + 스케줄러 등록 (실검증: 수동 트리거 curl)

### 리스크·한계
- 미확정 당일(전부 0) 제외 로직 필수(기존 `/investor` 백엔드가 이미 함 — 재사용).
- 알림 피로: 종목당 일 1회 상한, 같은 방향 전환은 7일 내 재알림 금지.

## F5. 매수 전 프리모템 + 무효화 조건 등록

### 목적
매수 기록 시 사유(reason)를 받으면 "이 논리가 깨지는 조건"을 구조화해 저장하고, 조건 발동 시 알린다. 예측이 아니라 **가설이 틀렸음을 가장 빨리 아는** 장치. 행동 학습(reason 태그)의 완성형.

### 설계
**생성** (`POST /premortem/{code}` body: {reason, avgPrice, qty}):
- facts는 AnalysisService의 사실 수집 재사용(공유 함수로 추출 검토).
- Claude 1회 호출(Sonnet, ModelRouter 신규 트리거 `premortem`), **JSON 출력 강제**:
```json
{
  "bullCase": "…", "bearCase": "…",
  "invalidations": [
    {"type": "price_below", "threshold": 320400, "anchor": "20일 저점", "description": "…"},
    {"type": "target_cut",  "description": "컨센서스 목표가 하향 전환 시"},
    {"type": "flow_exit",   "threshold": 5, "description": "외인 5일 연속 순매도 시"}
  ]
}
```
- **환각 가드**: threshold는 facts의 기술적 앵커/52주/본인 손절가 중에서만(A3 규칙 재사용). 파싱 실패 시 저장 안 하고 산문만 반환(폴백).
- type은 백엔드가 평가 가능한 화이트리스트로 제한: `price_below | price_above | target_cut | flow_exit | event_before`. 그 외 type은 표시용으로만 저장(평가 skip).

**저장**: `.data/premortem.json` — {code, createdAt, reason, invalidations[], active}. 단일 사용자 전제(현재 앱 구조). 멀티유저 확장 시 사용자 키 분리 필요 — v1 범위 밖.

**감시**: F4의 일일 잡에 평가 단계 추가(가격·목표가 추세·수급 연속일은 전부 기존 데이터). 발동 → Slack "무효화 조건 발동: 삼성전자 — 20일 저점 320,400원 이탈 (매수 사유: 수주 모멘텀)" + 해당 조건 비활성화(1회성).

**앱**: 매수 기록 시트에 "무효화 조건 만들기" 토글 → 결과를 상세 화면 '내 포지션' 카드 아래 표시(조건 목록 + 활성 상태).

### 슬라이스
- 5a: 백엔드 생성+저장+JSON 가드(curl 검증)
- 5b: 일일 잡 평가+Slack (수동 트리거 검증)
- 5c: 앱 UI(기록 시트 연동 + 조건 카드)

### 리스크·한계
- LLM 비용: 매수 기록당 1회(수동 행위 기반이라 자연 상한). 캐시 불필요.

## F6. AI 스탠스 적중률 배치 (종목 코멘트 채점)

### 목적
종목 분석 코멘트의 스탠스(긍정/중립/부정)를 태깅해 20거래일 후 실제 수익률과 대조 — 앱 AI의 편향(예: "리레이팅 종목에 만성 부정")을 정량 측정. F1~F5의 심판 데이터.

### 설계
- **기존 구분 주의**: 현재 앱의 "AI 적중률"은 *시장 방향 예측*(브리핑 vs 코스피) 채점이다(EdgeApi.kt 참고). 본 기능은 *종목 코멘트* 채점 — 별도 지표로 만들고 앱 표시도 구분할 것.
- 스탠스 추출: 프롬프트에 최종 줄 `[스탠스: 긍정|중립|부정]` 출력 요구 → 백엔드 파싱 후 본문에서 제거(iOS 파싱 계약 불변). 파싱 실패 시 스탠스 "미상"으로 기록(채점 제외). **주의: 이 형식 지시는 COMMON_RULES가 아니라 별도 후처리 지시 블록으로** — 요약/소제목 계약과 충돌하지 않게 맨 끝에.
- 기록: `.data/stance_log.jsonl` — {code, date, mode, stance, priceAtGen}. 분석 생성 시마다 append(캐시 적중 시엔 기록 안 함 — 중복 방지).
- 채점 배치: 주 1회 잡 — 20거래일 경과 건에 실제 수익률 조인 → {긍정→상승?, 부정→하락?, 중립→|수익률|<3%?} 채점. 집계: 전체/모드별/레짐 레이블별.
- `GET /stance-stats` → 앱 StatsView에 "종목 코멘트 적중률" 신규 항목.

### 슬라이스
- 6a: 스탠스 태그 출력+파싱+로그(분석 품질에 영향 없는지 실호출 확인)
- 6b: 채점 배치+엔드포인트+테스트
- 6c: StatsView 항목 추가

### 리스크·한계
- 20일 창은 임의적 — v1 고정, 조정은 데이터 쌓인 후.
- 스탠스 태그가 코멘트 톤에 영향 줄 수 있음(태그 때문에 억지로 방향을 정함) — "판단이 서지 않으면 중립을 선택하라"를 지시에 포함.
