## T1. 규율 채점 매매 시점 스냅샷 (Opus)

**배경(코치)**: 손절/익절 규율 채점이 매매 당시가 아닌 **현재 holding에 설정된** stop/target을 참조
(StatsView.swift:734-747 disciplineRows → :842-845 positionMap = 현재 holdingRepo.all()).
매도 후 손절가를 옮기면 과거 규율 성적이 바뀌고(자기기만 가능), 청산 후 holding 행을 지우면
그 쌍은 규율 집계에서 통째로 사라진다. 규율 거울은 조작 불가능해야 개입 효과가 있다 — 행동 개입 장치로서 치명적.

**스코프**:
1. `action_log`에 `stop_price`·`target_price` 컬럼 추가(nullable, 마이그레이션 N.sqm) —
   매수/매도 기록 시점의 holding 설정값을 스냅샷 저장. ActionLogRepository upsert 경로 수정.
2. 규율 채점(disciplineRows, iOS StatsView + Android StatsScreen)이 positionMap 대신
   **로그 행의 스냅샷 값**을 쓰도록 교체. 스냅샷 없는 과거 로그는 "설정 기록 없음"으로 집계 제외
   (현재값 폴백 금지 — 그게 바로 오염 경로).
3. 청산(holding 삭제) 후에도 쌍이 집계에 남는지 확인 — 스냅샷 기반이면 자동 해결.
4. iOS↔Android 같은 커밋(방법 A).

**검증**: 마이그레이션 관통(구 DB 시뮬), 스냅샷 저장→채점 반영 유닛/시뮬 확인,
손절가 사후 변경 시 과거 성적 불변 확인.
